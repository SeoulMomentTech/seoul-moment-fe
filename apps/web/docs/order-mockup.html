주문서 시안

장바구니에서 주문하기를 누른 뒤의 화면입니다. 결제는 LINE Pay와 ECPay 두 갈래이고 둘 다 외부 결제창으로 넘어가므로, 이 페이지의 역할은 주문 내용 확정과 배송지 입력까지입니다. 카드번호 같은 결제 정보는 우리 화면에서 받지 않습니다.

배송비는 브랜드별로 분리됩니다 — 장바구니를 브랜드 단위로 묶어둔 것과 같은 구조입니다. 그래서 주문서의 상품 목록도 브랜드 그룹을 유지하고 그룹마다 배송비가 붙습니다.

07

결정이 필요한 것

설계에 영향이 큰 것

  • 브랜드 내 배송비 산정 — shippingCost는 상품 단위 값입니다. 한 브랜드에서 상품 3개를 담으면 배송비를 합산할지, 최대값 하나만 받을지 정해야 합니다. 시안은 브랜드 내 최대값으로 그렸습니다(함께 발송되므로 중복 청구하지 않음).
  • 무료배송 기준 — 브랜드별 금액 기준 무료배송이 있는지. 있으면 그룹 헤더에 "NT$X 더 담으면 무료배송" 같은 유도 문구 자리가 필요합니다.
  • 이탈 복구 — 결제창은 리다이렉트라 우리 페이지를 떠납니다. 돌아왔을 때 주문서 입력값을 살릴지, 매번 새로 받을지 정해야 합니다. 살린다면 어디에 둘지(sessionStorage / 서버 주문 초안).
  • 주문 초안 시점 — 결제하기를 누를 때 서버에 주문을 먼저 만들고 결제창으로 보내는지(권장), 아니면 결제 성공 후에 만드는지. 전자면 실패 주문이 남고 후자면 금액 위조 검증이 어렵습니다.
  • 쿠폰·포인트 — 시안에 없습니다. 있으면 결제 금액 패널에 할인 행이 추가되고 최종 금액 계산이 바뀝니다.
  • 재고 검증 — 상품 API에 stock이 없습니다. 주문 시점에 품절을 어떻게 알릴지 정해야 합니다.

UI 판단 (되돌릴 수 있음)

  • 주문 상품은 읽기 전용 — 수량 변경·삭제를 주문서에서 못 합니다. 장바구니로 돌아가야 합니다. 주문서에서 고치게 하면 금액 재계산과 재고 검증이 얽힙니다.
  • 썸네일 80px — 장바구니의 120px보다 작게 했습니다. 주문서에서는 이미지가 주인공이 아니라 확인용입니다.
  • 섹션 상단 보더를 검정 1px로 — 장바구니는 rgba(0,0,0,.1) 구분선인데, 주문서는 서류 성격이라 섹션 구분을 더 강하게 했습니다.
  • 세부 결제수단을 나누지 않음 — ECPay 결제창이 카드·ATM·편의점을 자체 제공하므로 우리 화면에서 또 나누지 않았습니다.
  • 동의는 단일 체크 — 약관 2건을 개별 체크로 나누지 않고 하나로 묶었습니다. 법무 검토가 필요하면 개별 체크로 쪼갭니다.

재사용할 기존 코드

  • UserProfile (shared/services/user.ts) — name·postalCode·city·district·detailAddress가 기본 배송지 그대로입니다.
  • UserInfo.phone — 연락처 기본값. 비어 있으면 mypage의 PhoneVerificationFlow로 보냅니다.
  • features/mypage/lib/regions.ts + cityCountryData.json — 대만 24개 縣市 · 區 · ZipCode. locale에 따라 중문/영문 라벨을 고릅니다.
  • features/mypage/ui/ProfileSection.tsx — 주소 3단 select 폼이 이미 이 구조입니다.
  • entities/cart — groupCartLinesByBrand, getCartLineAmount, sumCartAmount를 주문서 금액 계산에 그대로 씁니다.
  • shared/ui/checkbox.tsx, shared/ui/fixed-box.tsx, shared/ui/select.tsx

시안에서 대체한 것

  • 폰트 — 실제는 Pretendard입니다. Artifact CSP가 jsDelivr 스타일시트를 막아 Inter + Noto Sans KR로 대체했습니다.
  • 이미지 — 색 블록입니다. 실제로는 BaseImage.
  • 정적입니다 — 라디오·체크박스·select는 상태를 보여주기 위해 고정된 모습입니다. 무동작 탭 스톱과 거짓 ARIA를 만들지 않으려고 실제 컨트롤이 아닌 span으로 그렸습니다.
  • 데이터 — 상품·브랜드·주소·주문번호·계좌 전부 예시입니다. 금액은 계산이 맞습니다 — 상품 NT$2,560 + NT$1,340 = NT$3,900, 배송비 NT$60 + NT$80 = NT$140, 합계 NT$4,040.
  • LINE Pay / ECPay 마크 — 실제 로고가 아니라 색 배지에 이름만 넣은 대체 표기입니다. 구현 시 각 사의 브랜드 가이드를 따라야 합니다.
