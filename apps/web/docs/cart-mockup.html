담아두기 성격의 장바구니입니다. 자체 결제는 만들지 않고 수량 조절·선택 삭제·총 상품 금액까지만 다룹니다. 실제 구매는 지금처럼 브랜드의 외부 몰에서 일어나고, 구매하기·주문하기는 비활성 자리로 예약해 둡니다.

상품상세 담기는 Figma 디자인을 1:1로 재현했습니다 — 옵션은 드롭다운 2개, 고른 조합이 회색 박스에 쌓이고, 그 아래 총 상품 금액과 3버튼. /cart 페이지는 디자인이 없어 그 어휘를 상속해 새로 설계했습니다. 어느 쪽인지 섹션마다 라벨로 표시했습니다.

02번은 옵션 축이 상품마다 다를 때의 분기입니다 — 의류는 색상·사이즈를 다 골라야 하고, 화장품처럼 용량·텍스처가 하나로 고정된 상품은 옵션 노출 없이 수량만 조절합니다.

Figma와 코드가 이미 다른 것 (장바구니 범위 밖)

  • 할인율 20% — 디자인은 판매가 옆에 brand orange로 할인율을 표시합니다. 현재 코드에 없고 API에도 필드가 없습니다.
  • 공유 아이콘 — 디자인은 제목 우측(데스크톱) / GNB(모바일)에 있습니다. widgets/share-modal은 이미 있으니 배선만 남았습니다.
  • 별 5개 리뷰 표시 — 코드는 별 1개 + 평점 숫자입니다.
  • 상품상세 전용 GNB — 디자인에는 뒤로가기 + 카트 + 공유의 전용 헤더가 있지만 코드는 전역 Header를 씁니다.
  • GNB 메뉴 — 디자인은 Product / Brand / Magazine + 검색, 코드는 Product / News입니다.

이번 작업에서는 건드리지 않습니다. 같이 정리할지는 별도 결정입니다.

코드에 이미 적용한 것

  • shared/services/product.ts — OptionType에 VOLUME·TEXTURE 추가. OptionValue·OptionType·DetailOption을 export로 열었습니다(장바구니 feature가 씁니다).
  • DetailOption을 Record → Partial<Record>로. 서버는 상품이 가진 축만 내려주는데 Record는 7개 축이 항상 존재한다고 타입이 보장해버려서 option.COLOR[0] 같은 접근이 런타임에 터집니다.
  • 중복 선언 제거 — interface OptionValue가 같은 파일에 두 번 선언되어 있었습니다. 멤버가 같아서 declaration merging으로 조용히 컴파일되고 있었습니다.
  • entities/product/lib/optionAxes.ts 신설 — OPTION_AXIS_ORDER(서버 JSON 키 순서에 의존하지 않기 위한 명시적 순서), OPTION_AXIS_LABEL_KEY, listProductOptionAxes(), formatOptionAxisValues(). views/product와 features/cart가 함께 쓰므로 FSD상 entities에 두었습니다.
  • ProductDetailPage.tsx — 하드코딩된 색상/사이즈 블록 2개를 축 순회로 교체. 색상은 COLOR[0].value만 쓰고 있어서 값이 여러 개면 나머지가 사라지던 문제도 함께 없어졌습니다.
  • i18n/messages/{ko,en,zh-TW}.json — volume texture material fit style 5개 키 추가. Google Sheet에 넣지 않으면 다음 pnpm i18n:sync에 사라집니다.

pnpm typecheck:web · pnpm lint:fix:web 통과.

결정이 필요한 것

  • 라인 단위 구매 ↗ — 시안에는 있었으나 구현에서 뺐습니다. GET user/cart 응답에 external이 없고, 라인마다 상세를 치면 N+1입니다. 응답에 추가되면 되살릴 수 있습니다.
  • /cart의 주문하기 — 상세의 구매하기와 짝을 맞춰 비활성 자리로 뒀습니다. 아예 없애도 됩니다.
  • 상세의 하트 버튼 — 디자인상 브랜드 줄 오른쪽과 CTA 옆에 둘 다 있습니다. 하나로 줄일지 정해야 합니다.
  • 축 판별 기준 — "SIZE가 있으면 선택형" 대신 값이 2개 이상인 축이 있으면 선택형으로 잡았습니다. 의류·화장품 두 케이스를 모두 만족하면서 립스틱(COLOR 여러 개 + SIZE 없음)이 깨지지 않습니다. SIZE 기준으로 고정하길 원하시면 알려주세요.
  • 배지 숫자 — 라인 개수로 뒀습니다. 수량 합이 아닙니다.
  • 비활성 버튼 문구 — 지금은 구매하기/주문하기 그대로 비활성입니다. "준비중"을 라벨에 넣을지, title로만 둘지 결정이 필요합니다.

구현 시 접근성 요구사항

  • 이 시안의 컨트롤은 정적 표현입니다 — 무동작 탭 스톱과 거짓 ARIA를 만들지 않으려고 실제 button이 아닌 span으로 그렸습니다.
  • selectbox — 네이티브 select 또는 shared/ui/select.tsx. 축 이름이 라벨이 되어야 합니다(플레이스홀더만으로 두지 않기).
  • 고정형 — selectbox가 없으므로 사용자는 무엇이 담기는지 라인 라벨(50ml/젤 크림)로만 압니다. 라벨을 장식이 아니라 읽히는 텍스트로 두고, 수량 스테퍼에 상품 맥락을 담은 aria-label을 붙입니다.
  • 체크박스 — 네이티브 input type="checkbox". 전체선택은 부분 선택 시 indeterminate.
  • 수량 — role="group" + aria-label, 숫자에 aria-live="polite", 1에서 − 비활성. 스테퍼 내부 버튼이 12px 아이콘이라 터치 타겟이 부족합니다 — 아이콘은 12px로 두고 히트 영역을 44px로 넓혀야 합니다.
  • 비활성 버튼 — disabled만 두면 이유를 알 수 없습니다. aria-describedby로 "준비중"을 연결합니다.
  • Drawer — DrawerTitle을 반드시 렌더합니다(필요하면 sr-only). Radix 요구사항입니다.

시안에서 대체한 것

  • 폰트 — 실제 서비스와 디자인 모두 Pretendard입니다. Artifact CSP가 jsDelivr 스타일시트를 막아서 이 시안은 Inter(라틴) + Noto Sans KR(한글)로 대체했습니다. 자폭과 자간이 미세하게 다릅니다.
  • 이미지 — 상품 사진 대신 색 블록입니다. 카트 라인은 선택된 컬러 옵션 색을 칩니다. 실제로는 BaseImage.
  • 로고 — /logo.png 대신 워드마크 텍스트.
  • 프레임 폭 — 상품상세/장바구니 데스크톱은 유동적으로 그렸고 콘텐츠 컨테이너만 실제와 같습니다(1200 / 1280). 상품상세 모바일은 Figma 캔버스와 같은 360px, /cart 모바일은 실제 기기 폭 390px입니다.
  • 데이터 — 상품·브랜드·가격 전부 예시이고 실제 브랜드가 아닙니다. 디자인의 예시 상품(실제 스포츠 브랜드)은 그대로 쓰지 않았습니다. 금액은 계산이 맞습니다 — 상세 NT$1,280 × 2줄 = NT$2,560 / 카트 선택 2건 NT$2,560 + NT$1,340 = NT$3,900.
  • 통화 — 디자인은 원이지만 코드가 toNTCurrency(NT$)이고 대만 서비스라 NT$로 그렸습니다.
